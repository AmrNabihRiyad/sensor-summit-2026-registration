# Sensors Summit 2026 - Google Apps Script Integration Guide

This directory contains the production-ready Google Apps Script backend reference implementation for the **Sensors Summit 2026** registration workflow.

---

## 1. Responsibilities

1. **Request Intake**: Receives registration payloads (`POST` as JSON).
2. **Backend Validation**:
   - Mandatory Personal Data Processing Consent (`registrationConsent === "Yes"`).
   - Registration categories: `Student`, `Graduate / Alumni`, and `Distinguished Guest / Professional`.
   - Attendance day restriction: Enforces Day 1 only for `Distinguished Guest / Professional` on the backend.
   - Mandatory professional fields for `Distinguished Guest / Professional`: Title (with conditional Other), Organization, and Organization Type (with conditional Other).
   - Referral sources (`referralSources` array) and conditional Ambassador Code (`ambassadorCode` required only if "Through an Ambassador" is checked).
   - Backend Fee Recalculation:
     - Student: 200 EGP regardless of day count (+ 100 EGP if transportation selected).
     - Graduate / Alumni: Day 1 only is Free (0 EGP, + 100 EGP if transport); Day 2 only is 200 EGP (+ 100 EGP if transport); Both days is 200 EGP (+ 100 EGP if transport).
     - Distinguished Guest / Professional: 0 EGP total (completely free).
   - Strict 12-digit ASCII payment transaction reference (`^[0-9]{12}$`) validated only when `calculatedTotalFee > 0`. Free registrations (0 EGP) do not require payment references or proof.
3. **Data Storage in Google Sheets**:
   - Preserves all 50 existing columns in exact established order.
   - Dynamically inspects the actual header row to map each value under its matching column header.
   - For Distinguished Guest registrations, maps professional title to `jobTitle` (column 31) and organization to `organization` (column 32) when using the standard 50-column schema, while also supporting extended columns 51-55 if configured.
4. **Google Drive File Uploads**: Decodes and saves base64 payment receipts and national ID cards to Google Drive when provided.
5. **Branded Confirmation Email**:
   - Uses `MailApp.sendEmail()` with `htmlBody`, inline logo blobs via `inlineImages` with `cid:` attachments loaded from Google Drive, and a plain-text fallback.
   - Includes all 7 IEEE Sensors Council Egypt Chapter social channels.
   - Strictly excludes sensitive personal data (National ID, transaction reference, uploaded Drive files).
   - Isolated in a `try...catch` block: email delivery failure is logged but **never** causes the registration to fail.
6. **Response Contract**: Returns `{ success: true, registrationId: "SS26-XXXXXX", emailSent: true/false }` to the frontend.

## 3. Deployment Instructions

1. **Open Google Sheet**:
   - Open the official Sensors Summit 2026 registrations sheet.
   - Confirm the tab name is `Registrations`.
2. **Open Apps Script Editor**:
   - Go to `Extensions` > `Apps Script`.
   - Replace the script contents with [`Code.gs`](file:///c:/Users/mo3ta/Documents/IEEE-Projects/sensor-summit-2026-registration/google-apps-script/Code.gs).
3. **Configure Constants in `CONFIG`**:
   - `SPREADSHEET_ID`: Leave empty if container-bound to the active spreadsheet, or paste the Sheet ID.
   - `DRIVE_FOLDER_ID`: (Optional) ID of the Google Drive folder for file uploads.
   - `EMAIL_SENDER_NAME`: `"IEEE Sensors Summit 2026 Organizing Committee"`
   - `ORGANIZER_EMAIL`: `"Amr_Nabih@ieee.org"`
4. **Deploy as Web App**:
   - Click `Deploy` > `New deployment`.
   - Type: `Web app`.
   - Description: `Sensors Summit 2026 Registration Backend v3`.
   - Execute as: `Me (your Google account)`.
   - Who has access: `Anyone`.
   - Click `Deploy` and review permissions (`Spreadsheets`, `Drive`, `Mail`).
5. **Endpoint Verification**:
   - If deploying to a new Web App URL, update `API_URL` in [`src/main.js`](file:///c:/Users/mo3ta/Documents/IEEE-Projects/sensor-summit-2026-registration/src/main.js).
   - If reusing the existing deployment, no frontend URL change is needed.

## 4. Security & Access Control Best Practices

1. **Google Drive Permissions (PII Protection)**:
   - Ensure the Google Drive folder specified in `DRIVE_FOLDER_ID` is strictly restricted to authorized organizing committee members only.
   - **Never** set the folder or file sharing settings to "Anyone with the link can view". National ID scans and payment screenshots contain sensitive personal identifiable information (PII).
2. **Google Sheets Permissions**:
   - The spreadsheet storing registration records must only be accessible to authorized event administrators.
   - Cells are automatically neutralized against spreadsheet formula injection (`sanitizeForSheet`) on submission.
3. **Daily Email Quotas**:
   - Standard `@gmail.com` accounts have a quota of **100 emails per day**.
   - Google Workspace / IEEE domain accounts (`@ieee.org`) have a quota of **1,500 emails per day**.
   - Deploying using a Google Workspace account is strongly recommended for large-scale registration volume.
4. **Execution Permissions**:
   - The Web App must execute as **Me** (the deployer) with access **Anyone**. Unauthenticated applicants can only create new registrations via POST; they cannot read, edit, or delete existing rows or query other attendees' records.
